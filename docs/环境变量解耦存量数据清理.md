# 环境与变量解耦后的存量数据处理

本次调整后：

- 环境用于维护请求基础地址 `base_url`，例如 `https://api.example.com`。
- 变量不再绑定环境，只区分全局变量和项目变量。
- 执行时仍支持 `{{base_url}}`，但它来自当前执行环境的 `base_url` 字段，不再来自变量表。

## 1. 执行迁移

在 PyCharm Terminal 中执行：

```powershell
cd E:\JG_API\api_test_platform
$env:DATABASE_URL="sqlite:///local_trial.db"
$env:ENABLE_SCHEDULER="true"
$env:APP_ENV="development"
..\venv\Scripts\python.exe -m flask --app run.py db upgrade
```

迁移会自动做两件事：

- 从旧变量中尽量识别域名变量，回填到对应环境的 `base_url`。
- 将旧变量的 `environment_id` 清空，使变量脱离环境。

自动识别的域名变量名包括：

```text
base_url
backend_test
host
domain
api_host
api_base_url
```

## 2. 检查环境基础地址

进入页面：

```text
环境与变量 -> 环境
```

检查每个环境的“请求基础地址”是否正确。

如果没有被自动迁移，请手动编辑环境并填写，例如：

```text
https://test-operation.nekoplan.com
```

## 3. 检查重复变量

旧数据按“环境 + 变量名”存储，解耦后如果不同环境下存在同名变量，会变成重复变量。

SQLite 检查 SQL：

```sql
select
  coalesce(project_id, 0) as project_scope,
  var_key,
  count(*) as count
from global_variable
group by coalesce(project_id, 0), var_key
having count(*) > 1;
```

如果查到重复项，请在页面中保留一个需要的变量，删除其他重复项。

## 4. 清理旧域名变量

确认环境的 `base_url` 已正确填写后，可以删除旧的域名类变量，例如：

```text
base_url
backend_test
host
domain
api_host
api_base_url
```

建议先在页面手动删除。确认无误后，也可以用 SQL 删除：

```sql
delete from global_variable
where lower(var_key) in (
  'base_url',
  'backend_test',
  'host',
  'domain',
  'api_host',
  'api_base_url'
);
```

## 5. 接口 URL 推荐写法

推荐接口库中的 URL 写相对路径：

```text
/api/vip/v1/vipCardPageList
```

执行时平台会自动使用当前环境的 `base_url` 拼接完整地址。

兼容旧写法：

```text
{{base_url}}/api/vip/v1/vipCardPageList
```

这里的 `{{base_url}}` 现在来自环境基础地址，不再来自变量表。
