### TD-1 MySQL 5.7 升级到 8.4 LTS

**为什么**

- MySQL 5.7 的主流支持已于 2023-10-31 结束，至今无安全补丁。
- 项目默认连接串、Docker 镜像与部署文档均锁定在 5.7。
- MySQL 8.4 LTS 的支持周期到 2032-04-30，是官方推荐的替代版本。

**影响范围**

- `config.py` 的默认 `DATABASE_URL`
- `docker-compose.yml` 中的 `image: mysql:5.7`
- `README.md` 第 2 节技术栈、5.3 建库说明
- `docs/Docker部署指南.md`

**需要重点验证的兼容点**

- 字符集与排序规则：现有 `utf8mb4_unicode_ci` 与 8.x 默认 `utf8mb4_0900_ai_ci` 的差异。
- `sql_mode`：8.x 默认启用 `ONLY_FULL_GROUP_BY`，需检查仪表盘等聚合查询（`app/services/dashboard_service.py`）。
- 认证插件：`caching_sha2_password` 与当前驱动 PyMySQL 的兼容性。
- 保留字与 JSON 字段行为差异。

**验收标准**

- [ ] 空库在 8.4 上跑通全部迁移（`flask db upgrade` 到 `0016_add_websocket_configuration`）
- [ ] 存量数据迁移后主要链路可用：项目、接口、用例、集合、报告、定时任务、数据工厂
- [ ] `docker compose up -d --build` 可启动且健康检查通过
- [ ] README 与 Docker 部署指南同步更新

### TD-2 SQLAlchemy 1.4 升级到 2.x

**为什么**

- SQLAlchemy 2.0.0 已于 2023-01-26 发布；当前锁定的 1.4.54 发布于 2024-09，之后 1.4 分支不再有版本更新。
- 运行时持续打印 `RemovedIn20Warning`（示例位置：`app/blueprints/interfaces.py:292`），属于必须偿还的技术债。

**影响范围**

- `app/models.py`
- `app/blueprints/*.py`、`app/services/*.py` 中的查询写法
- `app/extensions.py` 与 `config.py` 中的 SQLAlchemy 配置

**建议步骤**

1. 用 `SQLALCHEMY_WARN_20=1` 跑一遍测试与主要页面，把全部 2.0 不兼容用法整理成清单。
2. 按清单逐项改造，例如 `Query.get()` 改为 `db.session.get()`、消除隐式 join、替换字符串化查询条件。
3. 升级 `SQLAlchemy` 与 `Flask-SQLAlchemy` 版本后完整回归。

**验收标准**

- [ ] `SQLALCHEMY_WARN_20=1` 下运行测试不再出现 `RemovedIn20Warning`
- [ ] `python -m unittest discover -s tests` 全部通过
- [ ] 主要页面与执行链路手工回归通过

### TD-3 接入 CI

**为什么**

- 当前全部单元测试依赖本地手动执行，没有任何自动化卡口。
- 本次 Python 3.12 迁移暴露的问题（`backports.zoneinfo` 在 3.12 上无法安装）本可在提交时由 CI 直接发现。

**建议方案（仓库托管在 GitHub）**

- 新增 `.github/workflows/ci.yml`，触发条件为 push 与 pull request。
- 基本步骤：检出代码 → 安装 Python → 安装依赖 → 执行 `python -m unittest discover -s tests -t .`
- 进阶（可选）：增加 MySQL service 容器验证迁移链路；增加 `docker build` 校验镜像可构建。

**验收标准**

- [ ] 每次 push 自动运行测试，运行结果在提交记录中可见
- [ ] 主分支设置为必须通过检查才能合并

## 3. 暂不处理（已评估，收益有限）

| 项 | 现状 | 结论 |
|---|---|---|
| jQuery | 3.7.1（jQuery 4.0.0 已于 2026-01 发布） | 3.x 仍在维护，升级不影响功能，随缘处理 |
| Bootstrap | CDN 引入 5.3.3（最新 5.3.8） | 同一条 minor 线，仅补丁版差异 |
| 依赖补丁版本 | websocket-client、gunicorn、requests 等落后若干补丁版 | 属刻意锁定在验证过的版本，随下次统一升级处理 |
| pytz | 仍在使用 | 该库仍在维护，但 Python 3.9+ 已内置 zoneinfo，新代码不应再引入 |

## 4. 已知架构约束（非本次升级范围，仅作记录）

- **进程内状态**：`app/services/case_debug_service.py` 与 `app/services/websocket_debug_service.py` 的调试状态保存在进程内存中，APScheduler 也运行在 Web 进程内。因此 `README.md` 要求保持单个 Gunicorn worker，当前无法水平扩容。
- **执行同步阻塞**：集合执行在请求线程内同步完成（`app/blueprints/suites.py`），长时间执行的集合会占用请求线程。
- **无鉴权**：平台当前没有登录与权限模块。
- **测试覆盖盲区**：自动化测试运行在内存 SQLite 上，MySQL 路径没有自动化覆盖。

上述约束若未来需要多副本部署或承接大批量并发执行，需要先做架构调整，例如引入任务队列与独立调度进程。
