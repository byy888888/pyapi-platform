# 数据工厂功能说明

## 1. 功能定位

数据工厂用于在测试或开发验证期间，循环调用一个 HTTP 接口，或者按顺序调用多个存在依赖关系的 HTTP 接口，以批量构造测试数据。数据工厂使用独立的配置和执行历史，不生成测试报告，也不进入仪表盘定时任务统计。

## 2. 配置规则

- 工厂名称、默认执行环境为必填项。
- 所属项目和描述/备注为选填项。
- 未选择项目时，只能配置自定义 URL。
- 选择项目后，可以按“模块 -> 接口”分组引用当前项目的 HTTP 接口，也可以继续使用自定义 URL。
- 编辑页采用“工厂信息 + 图形流程 + 步骤配置”的三栏布局，直接在流程中新增、删除和调整步骤顺序，不需要预设步骤数。
- 流程支持接口步骤和等待步骤；等待步骤可配置 0.1 到 3600 秒的暂停时间。
- 引用接口库时只保存差异配置，执行时使用“接口库最新配置 + 工厂覆盖配置”。
- 接口步骤采用 Params、Body、Headers、响应提取、断言五个结构化页签，不使用 JSON 配置输入框。
- 每个工厂至少需要一个步骤；流程不设置单步启用开关。

## 3. 执行与变量

每轮中的步骤按照图形流程顺序串行执行，同一轮共享运行时变量，不同轮次相互隔离。底部只设置生成次数和并发数，不设置每轮间隔。变量语法如下：

```text
全局或项目变量：{{variable_name}}
本轮提取变量：${variable_name}
本次运行编号：${factory_run_id}
当前轮次：${iteration_no}
```

数据生成函数包括：

```text
${uuid()}
${timestamp()}
${random_int(1,100)}
${random_string(12)}
${random_mobile()}
```

JSONPath 提取器支持必填标记。必填提取失败会使接口失败；提取成功的变量可以通过 `${变量名}` 传递给当前轮的后续步骤。

接口步骤调试结果在当前编辑页面内按步骤缓存。切换 Params、Body、Headers、响应提取和断言页签，或临时切换到其他步骤后，最近一次调试响应仍会展示；刷新页面后调试缓存清空。JSONPath 点选只作用于当前激活的响应提取或断言页签，并优先填写最近获得焦点的输入框。

## 4. 成功和失败策略

接口默认需要满足：HTTP 请求正常完成、状态码为 2xx、必填提取器成功，以及配置的结构化断言全部通过。断言比较由后端按声明类型执行强类型校验，例如整数 `200` 不等于字符串 `"200"`。

接口步骤失败后固定停止当前轮，并继续执行下一轮，不再在工厂或步骤中暴露失败策略设置。

造数接口具有副作用，当前版本默认不做自动重试。

## 5. 执行历史

数据工厂采用后台执行，执行详情包含轮次进度、每个步骤的完整请求、完整响应、响应提取、断言及错误原因。请求参数、请求头和请求体分区展示；响应头和响应正文分区展示；各分区可以独立展开或收起。HTTP 状态码显示在步骤结果右侧。断言只展示名称、期望值、实际值和结果。等待步骤会展示设定等待时间和实际耗时。取消为协作式取消：当前已经发出的请求会等待返回或超时；等待步骤可及时响应取消；取消后不再启动后续步骤和轮次。

数据工厂用于直接构造测试数据，不提供执行结果导出功能。

敏感认证请求头会脱敏保存，响应正文完整保存。数据工厂不提供执行结果导出；大响应会增加数据库存储占用，应按实际造数接口控制响应规模和历史保留周期。

## 6. 第一版边界

当前版本仅支持 HTTP 和手动执行，暂不包含 WebSocket、定时执行、条件分支、跨轮变量依赖、文件数据驱动、自动重试和分布式任务队列。

数据工厂不单独配置初始运行变量。固定公共数据使用平台全局变量或项目变量；动态生成函数直接写在 URL、Params、Headers 或 Body 中；接口依赖值由前置接口提取后引用。
